## Codebase Patterns
- Repo git root è direttamente `mstickets/` (non un sottodirectory `orchestrator/` separato — quella
  cartella esiste ma è vuota/legacy, ignorarla). `git rev-parse --show-toplevel` conferma.
- Ambiente via `docker compose` (servizi `app`/`db`/`redis`/`queue`/`web`/`scheduler`/`mailpit`), già up in
  questa sessione. Comandi via `docker compose exec -T app ...`.
- **Isolamento test da dev DB**: `docker compose exec -T app env -u DB_CONNECTION -u DB_DATABASE -u DB_HOST
  -u DB_PORT -u DB_USERNAME -u DB_PASSWORD php -d memory_limit=512M vendor/bin/pest <path>` — necessario
  perché le env reali del container (iniettate da `env_file: .env`) altrimenti sovrascrivono gli `<env>` di
  `phpunit.xml` (gotcha già documentato in CLAUDE.md, ora forse mitigato da un fix in 3c0d277 "isolamento
  reale dell'ambiente di test" — verificato comunque che il workaround esplicito resta necessario/innocuo).
- Analyse: `docker compose exec -T app vendor/bin/phpstan analyse --memory-limit=1G`. Lint: `docker compose
  exec -T app vendor/bin/pint --test`.
- Il piano dettagliato `docs/superpowers/plans/2026-09-07-cai-scraper-native-php.md` contiene il codice
  ESATTO (migrazione, test, classi) da usare per ogni Task N ↔ US-90(N). Copiarlo alla lettera invece di
  reinventare, come richiesto dal PRD.
