## Codebase Patterns
- `app/Domain/<Modulo>/Policies/<Modello>Policy` è auto-scoperta da Laravel (namespace swap `\Models\`→`\Policies\`), nessun `AuthServiceProvider`/`Gate::policy()` da registrare in questo repo — già documentato in `orchestrator/CLAUDE.md:142`.
- Colonne `decimal:x` nei cast Eloquent tornano stringhe: quando servono in un calcolo, castare esplicitamente a `(float)`/`(int)` prima di usarle (es. `Tag::estimated_hours`, `Ticket::estimated_hours`).
- Query su colonne enum-cast (es. `tickets.status` → `TicketStatus`) accettano direttamente i case dell'enum in `where`/`whereNotIn`, non serve passare `->value`.
- Test Unit "puri" ma DB-backed vivono in `tests/Unit/Domain/<Contesto>/...Test.php` con `uses(RefreshDatabase::class);` in testa (niente PHPUnit class-based, solo funzioni Pest) — pattern seguito da `tests/Unit/Domain/Mail/Support/*`.
- Nessuna Model Factory per `Tag`/`Ticket`: nei test si costruisce con `Model::create([...])` diretto (pattern in `TagsTableTest`).
- La suite completa (`vendor/bin/pest`) su questa macchina richiede `php -d memory_limit=1G` (il default 128M in `php.ini` di Homebrew la esaurisce a metà, specialmente sui test che usano medialibrary/finfo). `php artisan test` non passa il flag `-d` al processo Pest interno: usare `vendor/bin/pest` direttamente quando serve più memoria.
- 10 test pre-esistenti e non correlati a questa fase falliscono su questa macchina locale per una lacuna dell'ambiente TeX Live (`csquotes.sty` mancante per pdflatex), usato solo dal PDF di collaudo (`CollaudoGenerateCommandTest`, `CollaudoGenerateDetailedTest`, `LatexPdfCompilerTest`) — non è una regressione introdotta in Fase 4, verificare/installare il pacchetto TeX mancante separatamente se il collaudo va rigenerato su questa macchina.
- Per uno screenshot di un'Action Filament/Livewire autenticata (click + form modale + submit, non solo una pagina pubblica), lo headless Chrome CLI da riga di comando non basta (nessuna interazione scriptabile): usare Playwright (`npx --yes playwright install chromium`, poi uno script `.mjs` in `/tmp`). I container Docker `app`/`web`/`db` di questo progetto NON sono avviati di default su questa macchina (solo `queue`/`scheduler`/`redis`): `docker compose up -d app web db` prima di navigare su `http://localhost:8080`. Dettagli completi in `orchestrator/CLAUDE.md`, sezione "Verifica in browser di un'Action Filament autenticata (US-402)".
- Una colonna Filament con markup HTML non banale (es. una barra di progresso) va fatta con `Filament\Tables\Columns\ViewColumn::make(...)->view('filament.tables.columns.mia-vista')` (la vista riceve `$record` direttamente), MAI con `TextColumn->html()->formatStateUsing(fn () => new HtmlString(...))`: il wrapper `fi-ta-text-item` di `TextColumn` tronca/comprime `<div>` a blocco annidati. Inoltre qualunque classe Tailwind usata solo in una vista Blade nuova non compare finché non si lancia `npm run build` (nessun dev server Vite in watch su questa macchina, `public/build/` non tracciato da git): un HTML corretto via `grep` ma uno screenshot "vuoto" è il sintomo. Dettagli in `orchestrator/CLAUDE.md`, sezione "Colonna custom con markup HTML in una tabella Filament (barra SAL, US-403)".
- **Checkpoint di fine fase (US-4x1/US-5x1/...)**: aggiungere un nuovo `docs/collaudo/0N-fase-N.md` richiede SEMPRE di rinumerare `0N-registro-esiti.md`/`0N-verbale-collaudo.md` in avanti (verificare lo schema con `git log --diff-filter=R --summary --oneline -- docs/collaudo/`, mai indovinare il numero) E di aggiornare le 3 costanti hardcoded in `app/Console/Commands/CollaudoGenerateCommand.php` (`COMMON_SUFFIX_FILES`, `FASE_NARRATIVE_FILES`, `FASE_TITLES`) — senza quest'ultimo aggiornamento `collaudo:generate N` produce silenziosamente solo il PDF sintetico invece di quello dettagliato, nessun errore esplicito. Un test Pest con un apostrofo nel nome referenziato nel manifest rompe `collaudo:verify-manifest` (confronto byte-a-byte: il file sorgente ha `\'`, la stringa PHP valutata dal manifest ha `'`) — scegliere sempre un test equivalente senza apostrofo.
