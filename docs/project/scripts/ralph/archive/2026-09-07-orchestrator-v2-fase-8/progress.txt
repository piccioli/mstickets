## Codebase Patterns
- Progetto: `mstickets/orchestrator` (Laravel, Filament), git separato dalla root `mstickets/` (che non è
  un repo git). Ambiente via `docker compose` (servizi `app`/`db`/`redis`/`queue`/`web`/`scheduler`/
  `db_legacy`), già up in questa sessione — comandi con `docker compose exec app ...`, non `php artisan`
  sull'host (l'host non risolve l'hostname `db`).
- Comandi qualità: `docker compose exec app composer analyse` (phpstan/larastan, level 6), `docker compose
  exec app vendor/bin/pint --test` (lint), `docker compose exec app php artisan test` (Pest, DB sqlite
  :memory: per i test — vedi gotcha sotto sul crash del suite completo).
- Migrazioni: `database/migrations/YYYY_MM_DD_HHMMSS_create_<tabella>_table.php`, classe anonima,
  `declare(strict_types=1)`, `Schema::create`/`dropIfExists`. FK standard: `$table->foreignId('x')
  ->nullable()->constrained('users')->nullOnDelete()`.
- Modelli: `App\Domain\<Dominio>\Models\*`, `Model` puro (nessuna base class custom), attributo PHP
  `#[Fillable([...])]` (non `protected $fillable`), cast via `protected function casts(): array` (stile
  Laravel 11+, richiede `parseModelCastsMethod: true` in phpstan.neon per l'inferenza tipo enum), relazioni
  tipizzate `BelongsTo`/`HasMany` con PHPDoc `@return BelongsTo<Target, $this>`.
- Nessuna factory dedicata per modelli di dominio (solo `database/factories/UserFactory.php`): nei test si
  usa `Model::create([...])` diretto + `User::factory()->create()`.
- Test di schema/relazioni: `tests/Feature/Domain/<Dominio>/*Test.php` (non `tests/Unit/Domain`, che è per
  enum/state machine), `uses(RefreshDatabase::class)`, `Schema::hasColumns(...)` per le colonne attese.
- **Per qualunque comando di import da una fonte dati reale**: se il file/dump reale è disponibile in
  locale, eseguire sempre il comando anche contro quello (non solo contro la fixture di test) prima di
  dichiarare la story completa — i test verdi su fixture non garantiscono che la forma dei dati reali sia
  quella attesa (vedi US-802: 2 bug reali, 0 dei quali coperti dalla fixture iniziale, entrambi trovati
  solo eseguendo contro `cai-datapack/runts-cai.sqlite`).
- Se il log di un'iterazione precedente mostra "Background tasks still running after 600s; terminating":
  il lavoro dell'agente in background non è perso, resta uncommitted nel working tree del branch —
  verificarlo e riprenderlo, non ripartire da zero.
- **Gotcha grosso**: `php artisan test` senza filtri crasha in modo deterministico e preesistente (non
  causato da alcuna story di questa fase), sempre nello stesso punto, subito prima di
  `tests/Unit/Domain/Mail/Parsers/*` (uso di `symfony/html-sanitizer` → `\Dom\HTMLDocument`, verosimile bug
  nativo dell'estensione PHP 8.4). Verificato riproducibile identico anche su un `git stash` pulito. Per
  "Tests pass" su una story che non tocca il dominio Mail: filtrare i test della propria story/dominio, non
  fidarsi del codice di uscita della run senza filtri. Dettagli completi in `orchestrator/CLAUDE.md`, sezione
  US-801.
- **Download di file da un'azione Filament**: un'`Action::make()->action(fn () => response()->streamDownload(...))`
  funziona come download browser out-of-the-box (Livewire intercetta nativamente il ritorno
  `StreamedResponse`/`BinaryFileResponse` di un metodo, nessun controller/route dedicato necessario). In
  test: `Livewire::test(...)->callTableAction('nomeAzione')`, poi `$test->effects['download']` (proprietà
  magica, non `assertFileDownloaded()` se serve ispezionare il contenuto). Dettagli completi in
  `orchestrator/CLAUDE.md`, sezione "Export di file da un'azione Filament".
- **Dati geografici reali col rumore**: prima di un `fitBounds()`/qualunque calcolo di viewport su
  coordinate provenienti da un import reale, verificare sempre con lo screenshot vero (non solo la fixture)
  — il datapack RUNTS-CAI contiene almeno un outlier geocodificato fuori dall'Italia che, non gestito,
  rende una mappa inutilizzabile pur passando tutti i test automatici.

     `CaiDatapackImporter::toCoordinate()` che scarta a `null` qualunque |valore| >= 1000 invece di far
     fallire l'import.
