## Codebase Patterns
- Enum backed semplici in `app/Domain/<Dominio>/Enums/`: `enum Foo: string { case Bar = 'bar'; ... }`,
  cast sul model via `protected function casts(): array { return ['col' => Foo::class]; }` (stile
  `TicketPriority`/`TicketStatus` su `Ticket`, ora anche `CustomerType`/`Region` su `User`). Implementano
  `Filament\Support\Contracts\HasLabel`/`HasColor`/`HasIcon` solo quando servono davvero per un badge/Select
  Filament nella story corrente — vedi `TerritorialScope` (solo `HasLabel`) vs `UserRole`/`TicketPriority`
  (tutti e tre). Non aggiungere i contratti Filament "per uniformità" se l'AC della story non li richiede:
  la story successiva che introduce la UI li aggiunge quando servono.
- Quality gate su questo repo (host, non Docker): `composer analyse` (Larastan) e `composer lint` (Pint)
  vanno bene così come sono. Per i test, **non usare `composer test`/`php artisan test`** sulla suite
  intera: va in OOM a 128M perché il comando `artisan test` rilancia PHPUnit in un processo figlio senza
  propagare `-d memory_limit`. Usare invece `php -d memory_limit=1G vendor/bin/pest` (stesso processo,
  propaga l'ini setting). Con questo workaround restano 10 failure pre-esistenti, tutte in
  `CollaudoGenerateCommandTest`/`CollaudoGenerateDetailedTest`/`LatexPdfCompilerTest` per `csquotes.sty`
  mancante nell'installazione TeX locale (documentato anche in `orchestrator/CLAUDE.md` righe ~301,
  ~499-505): non sono una regressione se il diff della propria story non tocca quei file/l'ambiente LaTeX.
  Il comando `php artisan test --filter=...` su un sottoinsieme mirato di solito non serve il workaround.
- I query object `App\Domain\*\Queries\*Query::for(User $user)` (§8.5 style) non presumono
  `$user === Auth::user()`: `Ticket::scopeVisibleTo()` chiama `$user->can(...)` sul parametro ricevuto, quindi
  `MyTicketsQuery::for($qualsiasiUtente)` funziona correttamente per calcolare metriche (es. conteggio ticket
  aperti) su un utente DIVERSO da quello autenticato, senza duplicare la logica di dominio in una query nuova.
- Checkpoint di fine fase (processo di collaudo, CLAUDE.md): quando si aggiunge `docs/collaudo/fase-N.php`,
  **verificare subito** se `App\Console\Commands\CollaudoGenerateCommand::FASE_NARRATIVE_FILES`/`FASE_TITLES`
  include già la chiave `N` — l'esistenza del manuale `NN-fase-N.md` da sola NON basta perché
  `collaudo:generate N` produca il PDF dettagliato: se la chiave manca, il comando ripiega silenziosamente
  (nessun errore) sul solo PDF sintetico dal manifest. Trovato mancante per Fase 6 durante US-706 (Fase 7):
  corretto insieme a Fase 7 nello stesso commit. Un manuale `NN-fase-N.md` di decine di test ripetitivi
  conviene generarlo con un piccolo script PHP monouso (mai committato) che legge il manifest e riproduce
  esattamente il template già in uso in una fase precedente — MA occhio alle celle di
  `01-matrice-tracciabilita.md`/`11-registro-esiti.md`: un carattere `|` letterale nella `descrizione` del
  manifest deve essere escapato a `\|`, altrimenti rompe silenziosamente la tabella markdown (bug distinto
  dal problema noto dell'apostrofo in `collaudo:verify-manifest`).

- **Learnings for future iterations:**
  - **Gotcha serio, ripetibile in futuro**: `#[Fillable([...])]` sul model `User` (attributo PHP, non
    `$fillable` Eloquent) è la lista REALE di colonne scrivibili da un `$record->update($data)` Filament.
    Una colonna nuova (anche se castata a enum e presente nello schema del form) che manca da questa lista
    viene scartata SILENZIOSAMENTE da `update()` — nessun errore, nessuna eccezione, il test fallisce solo
    sul valore persistito dopo `fresh()`. Ho perso ~40 minuti di debug (log su `mutateFormDataBeforeSave`
    per confermare che `$data` conteneva già il valore corretto) prima di trovare la vera causa. Se un
    campo Filament "sembra salvarsi" (nessun errore di validazione, `assertHasNoFormErrors()` passa) ma il
    valore persistito resta quello vecchio/null, controllare SEMPRE questo attributo per primo.
  - **Gotcha Filament v4 non ovvio**: `->visible(fn (Get $get) => ...)` + `->dehydrated(fn (Get $get) =>
    ...)` NON bastano per azzerare esplicitamente un campo quando diventa non pertinente (es. `region`
    quando `customer_type` passa da Sezione a Generico) — di default un campo nascosto viene escluso dalla
    dehydration A PRESCINDERE da `->dehydrated(true)` (quel metodo governa solo la dehydration di un campo
    VISIBILE). Serve `->dehydratedWhenHidden()` (proprietà distinta, default `false`) insieme a
    `->dehydrateStateUsing()` per forzare l'inclusione (e l'azzeramento) anche da nascosto. Pattern completo
    documentato in `CLAUDE.md` (root del progetto Laravel, non questo `progress.txt`).
  - `roles` è un `CheckboxList` legato a `->relationship('roles', 'name', ...)` (BelongsToMany Spatie): il
    suo stato via `Get $get('roles')` è un array di ID di ruolo, non di nomi — per verificare "è selezionato
    il ruolo customer" serve risolvere l'ID (`SpatieRole::query()->where('name', ...)->value('id')`) e fare
    `in_array()`, non confrontare stringhe.
  - Verifica in browser fatta con Playwright (`npx --yes playwright install chromium` già in cache da story
    precedenti, ma versione npm disallineata: usato `chromium.launch({channel: 'chrome'})` per riusare
    Google Chrome.app di sistema invece di scaricare un nuovo binario). Utente admin/target di verifica
